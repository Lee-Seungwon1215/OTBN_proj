# Classic McEliece `pk_gen()` 내부 시간 프로파일

측정일: 2026-08-02  
대상: libmceliece `348864/vec`, Apple Silicon ARM64, Apple clang `-O2`

## 측정 범위

- `pk_gen()` 한 번이 끝까지 성공한 경우
- `keypair()`가 성공할 때까지 발생한 `pk_gen()` 실패·재시도까지 포함한 경우
- 독립 실행 2회 × 11개 trial × trial당 키 생성 30회 = 성공 키 생성 660회
- 준비 실행 10회를 포함한 KEM 캡슐화·역캡슐화 670회로 결과 정확성 확인

가우스 소거가 가장 크다.

실패한 호출은 대부분 피벗 검사 도중 종료된다. 따라서 실제 `keypair()`를
빠르게 만드는 목적에서는 피벗 탐색과 전방 소거가 합계 77.28%로 명확한
최적화 1순위다.

## 코드 반복 횟수와 시간의 대응

`348864/vec`에서는 `GFBITS=12`, `PK_NROWS=768`, 전체 행렬 폭은 55개의
64비트 블록이고 체계형 왼쪽 부분은 12블록이다.

| 코드 단계 | 성공 호출당 주요 64비트 masked-XOR 수 | 성공 시간 비율 |
|---|---:|---:|
| 선형맵 적용 | 25,362,432 | 32.98% |
| 피벗 탐색 | 7,068,672 | 26.56% |
| 전방 소거 | 7,068,672 | 26.06% |
| 후방 소거 | 3,534,336 | 9.36% |

따라서 두 관점은 다음처럼 구분해야 한다.

- 코드상 가장 큰 단일 반복문: 선형맵 적용
- 성공 호출의 가장 큰 연산군: 가우스 소거 전체
- 실패 재시도를 포함한 실제 키 생성 병목: 피벗 탐색 + 전방 소거

## OTBN·RISC-V 적용 해석

이 병목의 핵심 명령은 큰 정수 곱셈이 아니라 64비트 블록의 마스크 생성,
AND, XOR, 행 순회다. `mat`과 `ops`만 합쳐도 약 402 KiB이므로 연산기 폭뿐
아니라 데이터 이동과 메모리 배치가 성능을 좌우한다.

- 실제 키 생성 최적화 1순위: 피벗 탐색·전방 소거의 넓은 행 masked-XOR
- 그다음: 성공한 호출에서만 수행되는 선형맵 적용
- OTBN 실험 시: 256비트 WDR 연산보다 먼저 행 타일을 DMEM에 넣고 빼는
  비용을 포함해 측정해야 한다.
- RISC-V 확장 시: `mask`로 여러 워드를 갱신하는 명령 또는 행 단위
  스트리밍 구조가 후보이며, 캐시·메모리 대역폭을 함께 설계해야 한다.

이 결과는 ARM64 portable `vec` 구현의 프로파일이다. AVX 구현이나 향후
RISC-V/OTBN 구현에서는 내부 알고리즘과 메모리 계층이 달라지므로 절대시간을
그대로 옮기지 않고, 동일한 구간 계측을 다시 수행해야 한다.
